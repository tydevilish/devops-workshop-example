Clone โปรเจค & ตั้งค่าไฟล์พื้นฐาน

เริ่มต้นด้วยการนำโปรเจคจาก GitLab มาไว้บนเครื่องของเรา จากนั้นสร้างไฟล์เว็บ (index.html) และไฟล์ตั้งค่า Web Server (nginx.conf) ซึ่งเป็นรากฐานสำคัญก่อนจะทำ CI/CD

สร้างไฟล์ nginx.conf
สร้างไฟล์ใหม่อีกไฟล์ชื่อ nginx.conf — ไฟล์นี้คือ "คู่มือ" บอก Nginx (Web Server) ว่าให้ทำงานอย่างไร
📸 สร้างไฟล์ nginx.conf
9
เขียน config ลงใน nginx.conf
วางโค้ดด้านล่างลงในไฟล์ nginx.conf — config นี้ทำ 3 สิ่ง: รับ request ที่พอร์ต 80 / ซ่อนเวอร์ชัน Nginx เพื่อความปลอดภัย / เปิด Gzip บีบอัดไฟล์ให้เว็บโหลดเร็วขึ้น
Nginx Config 
server {
    listen 80;
    server_name localhost;

    # ซ่อนเวอร์ชัน Nginx ไม่ให้ Hacker ทราบ
    server_tokens off;

    location / {
        root   /usr/share/nginx/html;
        index  index.html;
    }

    # เปิด Gzip: บีบอัดไฟล์ก่อนส่ง → เว็บโหลดเร็วขึ้นมาก
    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_types text/plain text/css application/json
               application/javascript text/xml application/xml text/javascript;
}
🔒
server_tokens off — ปกติ Nginx จะประกาศเวอร์ชันตัวเองใน HTTP header ซึ่ง Hacker ใช้หาช่องโหว่ได้ การปิดมันทำให้ปลอดภัยขึ้นโดยไม่ต้องทำอะไรเพิ่ม
📸 หน้าตาไฟล์ nginx.conf หลังจากเขียนเสร็จ
Part 2

สร้าง Dockerfile & Docker Compose

Docker คือเครื่องมือที่ทำให้เว็บของเราทำงานได้ในทุก Server โดยไม่ต้องติดตั้งอะไรเพิ่ม เราจะสร้าง 2 ไฟล์ — Dockerfile (สูตรสร้าง Container) และ docker-compose.yml (วิธีรัน Container บน Server)

🐳 Dockerfile
🗂️ docker-compose.yml
🔢 Port Mapping
10
สร้างไฟล์ Dockerfile
สร้างไฟล์ใหม่ชื่อ Dockerfile (ตัว D ใหญ่ ไม่มีนามสกุล) ไฟล์นี้คือ "สูตร" บอก Docker ว่าจะสร้าง Image (กล่อง) ของเว็บเราออกมาอย่างไร
📸 สร้างไฟล์ Dockerfile ใน VS Code
11
เขียนโค้ดใน Dockerfile
วางโค้ดด้านล่างลงใน Dockerfile — Docker จะทำตามคำสั่งทีละบรรทัด: ดึง Nginx Alpine → ใส่ config → ใส่ไฟล์เว็บ → เปิดพอร์ต 80 รอรับ request
Dockerfile 
# ใช้ Nginx เวอร์ชัน Alpine (ขนาดเล็กมาก ~5MB ประหยัดทรัพยากรสุดๆ)
FROM nginx:alpine

# เอาไฟล์ตั้งค่า Nginx ของเราไปทับค่า default ของระบบ
COPY nginx.conf /etc/nginx/conf.d/default.conf

# เอาไฟล์เว็บทั้งหมดไปไว้ใน folder ที่ Nginx แสดงผล
COPY . /usr/share/nginx/html

# เปิดพอร์ต 80 บน Container นี้ (พอร์ต HTTP มาตรฐาน)
EXPOSE 80

# สั่งให้ Nginx ทำงาน foreground (ระบบจะรู้ว่ายัง alive อยู่)
CMD ["nginx", "-g", "daemon off;"]
🏔️
nginx:alpine — Alpine Linux มีขนาดเพียง ~5MB (เทียบกับ Ubuntu ~70MB) ทำให้ Image มีขนาดเล็ก download เร็ว และมีช่องโหว่น้อยกว่า
📸 โค้ด Dockerfile ใน VS Code
12
สร้างไฟล์ docker-compose.yml
สร้างไฟล์ชื่อ docker-compose.yml — ไฟล์นี้คือ "แผนผัง" บอกว่าจะรัน Container ของเว็บอย่างไรบน Server จริง ไฟล์นี้จะถูกส่งไปรันบน Server ในขั้นตอน Deploy
📸 สร้างไฟล์ docker-compose.yml
13
เขียนโค้ดใน docker-compose.yml
วางโค้ดด้านล่าง — ต้องแก้ 2 จุด: เปลี่ยน username เป็นชื่อ GitLab ของคุณ และเปลี่ยน 99xx เป็น Port ที่ได้รับมอบหมาย
YAML 
services:
  web:
    # ดึง Image ที่ Build แล้วจาก GitLab Container Registry
    image: registry.gitlab.com/username/my-project:latest
    container_name: my_website

    ports:
      # [Port บน Server]:[Port ของ Container]
      # เปลี่ยนเฉพาะฝั่งซ้าย (99xx) เป็น Port ที่ได้รับมอบหมาย
      - "99xx:80"

    # รีสตาร์ทอัตโนมัติเสมอ (ยกเว้นถ้าเราสั่งหยุดเอง)
    restart: unless-stopped

    # จำกัดขนาด Log ไม่ให้กิน Disk จนเต็ม
    logging:
      driver: "json-file"
      options:
        max-size: "10m"
        max-file: "3"
⚠️
อย่าลืมเปลี่ยน username เป็น GitLab username ของคุณ (ต้องเป็นตัวพิมพ์เล็กทั้งหมด หากมีตัวพิมพ์ใหญ่ให้แก้เป็นตัวพิมพ์เล็กให้หมด) และ 99xx เป็น Port ที่ได้รับมอบหมายตามตารางด้านล่าง มิฉะนั้น Deploy จะ Error

ตั้งค่า CI/CD Pipeline

CI/CD Pipeline คือระบบอัตโนมัติที่ทำงานทุกครั้งที่เรา push โค้ดขึ้น GitLab — มันจะ Build โค้ดให้เป็น Docker Image, Test ว่าไฟล์ HTML ถูกต้อง, แล้ว Deploy ขึ้น Server โดยอัตโนมัติ ไม่ต้องทำเองสักขั้นตอน

🔨 Build
🧪 Test
🚀 Deploy
15
เปิดไฟล์ .gitlab-ci.yml
ไฟล์ .gitlab-ci.yml คือ "สมองกล" ของ CI/CD — GitLab จะอ่านไฟล์นี้และทำงานตามคำสั่งทุกครั้งที่มีการ push โค้ด เราเคยสร้างไว้แล้วในเวิร์กชอปก่อนหน้า ให้เปิดขึ้นมา
📌
ชื่อไฟล์นี้ขึ้นต้นด้วย . (จุด) ทำให้ซ่อนอยู่บน Linux/Mac ถ้าหาไม่เจอใน VS Code ให้กด Cmd+Shift+P แล้วพิมพ์ชื่อไฟล์ค้นหา

เขียน Pipeline 3 ขั้นตอน
วาง config ด้านล่างลงในไฟล์ Pipeline จะมี 3 ขั้นตอนที่ทำงานต่อกันโดยอัตโนมัติเมื่อ push โค้ดขึ้น branch main
🔨
1. Build
สร้าง Docker Image แล้วดันขึ้น GitLab Registry
→
🧪
2. Test
ตรวจสอบความถูกต้องของ HTML ด้วย tidy
→
🚀
3. Deploy
SSH เข้า Server สั่งดึง Image มารันอัตโนมัติ
YAML — .gitlab-ci.yml 
stages:
  - build
  - test
  - deploy

variables:
  # ตั้งชื่อ Image ให้เป็นมาตรฐาน โดย GitLab จะเติมข้อมูลให้อัตโนมัติ
  IMAGE_TAG: $CI_REGISTRY_IMAGE:latest

# ==========================================
# 1. BUILD: สร้าง Docker Image → ดันขึ้นโกดัง GitLab
# ==========================================
build:
  stage: build
  image: docker:24
  services:
    - docker:24-dind    # Docker-in-Docker: รัน Docker ภายใน Runner
  script:
    - docker login -u $CI_REGISTRY_USER -p $CI_REGISTRY_PASSWORD $CI_REGISTRY
    - docker build -t $IMAGE_TAG .  # สร้าง Image จาก Dockerfile
    - docker push $IMAGE_TAG         # ส่ง Image ขึ้น GitLab Registry
  only:
    - main  # ทำงานเฉพาะเมื่อ push ไปที่ branch main

# ==========================================
# 2. TEST: ตรวจสอบ HTML ว่า syntax ถูกต้องไหม
# ==========================================
test:
  stage: test
  image: alpine:latest
  needs: ["build"]  # รอให้ Build เสร็จก่อน
  script:
    - apk add --no-cache tidyhtml  # ติดตั้ง HTML validator
    - tidy -q -e index.html; [ $? -le 1 ]
  only:
    - main

# ==========================================
# 3. DEPLOY: SSH เข้า Server → ดึง Image → รันเว็บ
# ==========================================
deploy:
  stage: deploy
  image: alpine:latest
  needs: ["test"]  # รอให้ Test ผ่านก่อน
  before_script:
    - apk add --no-cache openssh-client sshpass
  script:
    # สร้างโฟลเดอร์รอไว้บน Server
    - sshpass -p "$SERVER_PASSWORD" ssh -o StrictHostKeyChecking=no
      "$SERVER_USER@$SERVER_IP" "mkdir -p ~/deploys/$CI_PROJECT_PATH_SLUG"

    # ส่งไฟล์ docker-compose.yml ข้ามอินเทอร์เน็ตไปวางที่ Server
    - sshpass -p "$SERVER_PASSWORD" scp -o StrictHostKeyChecking=no
      docker-compose.yml $SERVER_USER@$SERVER_IP:~/deploys/$CI_PROJECT_PATH_SLUG/

    # สั่ง Server: login GitLab → ดึง Image ใหม่ → รันเว็บ
    - >
      sshpass -p "$SERVER_PASSWORD" ssh -o StrictHostKeyChecking=no
      "$SERVER_USER@$SERVER_IP" "
      cd ~/deploys/$CI_PROJECT_PATH_SLUG &&
      docker login -u $CI_REGISTRY_USER -p $CI_REGISTRY_PASSWORD $CI_REGISTRY &&
      docker compose pull &&
      docker compose up -d
      "
  only:
    - main
🔐
ตัวแปรอย่าง $SERVER_PASSWORD, $SERVER_IP, $SERVER_USER จะถูกตั้งค่าใน GitLab Settings ในขั้นตอนถัดไป — ไม่ต้องพิมพ์ข้อมูลจริงลงในโค้ดให้ปลอดภัยกว่า
📸 โค้ด .gitlab-ci.yml ครบทั้ง 3 stage ใน VS Code

git commit — บันทึก snapshot ของโค้ด
git commit คือการบันทึก "ภาพถ่าย" ของโค้ด ณ เวลานี้ พร้อมข้อความอธิบายว่าทำอะไรไป — -m ย่อมาจาก message
Bash 
git commit -m "feat: Add index, Dockerfile, docker-compose, gitlab-ci, nginx"
📸 รัน git commit พร้อม message
21
เปลี่ยนชื่อ branch เป็น main
ในไฟล์ .gitlab-ci.yml เราระบุว่า Pipeline ทำงานเฉพาะ branch main เท่านั้น ดังนั้นต้องมั่นใจว่า branch ปัจจุบันชื่อ main ก่อน push
Bash 
git branch -m main
🌿
git branch -m main คือการ "rename" branch ปัจจุบันให้ชื่อ main — ถ้า branch ชื่อ main อยู่แล้วก็ไม่มีผลอะไร แค่ทำให้แน่ใจ
📸 เปลี่ยนชื่อ branch เป็น main
22
git push — ส่งโค้ดขึ้น GitLab
คำสั่งนี้ส่งโค้ดทั้งหมดที่ commit ไว้ขึ้น GitLab และตั้ง upstream tracking ให้ด้วย (-u ย่อมาจาก upstream) เพื่อให้ครั้งต่อไปพิมพ์แค่ git push ได้เลย
Bash 
git push -u origin main
📸 รัน git push -u origin main
📸 ผลหลัง push สำเร็จ
24
กลับไป GitLab — ดู Pipeline เริ่มทำงาน
กลับไปที่ GitLab และเข้าโปรเจค my-project จะเห็นไฟล์ที่เรา push ขึ้นมาแล้ว และสังเกตที่ commit ล่าสุดจะมี ไอคอนกลม สีส้ม/เหลืองข้างๆ แสดงว่า Pipeline กำลังทำงานอยู่
⏳
ตอนนี้ Pipeline อาจ Error อยู่ เพราะเรายังไม่ได้กำหนด Variables ที่จำเป็น เดี๋ยวเราจะทำในขั้นตอนถัดไป ไม่ต้องตกใจ!
📸 ไอคอนกลมข้าง commit แสดงสถานะ Pipeline

อ่าน Deploy Log
จะเห็น log การทำงานแบบ real-time: ติดตั้ง SSH → เชื่อมต่อ Server → login GitLab Registry → ดึง Image → รัน Container — ถ้าสำเร็จจะขึ้น Job succeeded บรรทัดสุดท้าย
$ apk add --no-cache openssh-client sshpass (1/7) Installing openssh-keygen ... OK: 11.8 MiB in 23 packages $ sshpass -p "$SERVER_PASSWORD" ssh ... "mkdir -p ~/deploys/..." Warning: Permanently added '[MASKED]' (ED25519) to known hosts. $ docker login ... && docker compose pull && docker compose up -d Login Succeeded Image registry.gitlab.com/username/my-project:latest Pulling 6ca27e509c31 Pull complete d9cb6464796a Pull complete Image registry.gitlab.com/username/my-project:latest Pulled Container my_website Recreated Container my_website Started Cleaning up project directory and file based variables Job succeeded
📋
เห็น "Job succeeded" บรรทัดสุดท้าย = สำเร็จ 🎉 | เห็น "Job failed" = กด Retry ที่ด้านบนขวา แล้วรอดูอีกรอบ
📸 Deploy log แสดง Job succeeded
